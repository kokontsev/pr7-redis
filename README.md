# Практическая работа 7

Redis и время жизни ключей.

Кэш обёрнут в отдельный пакет internal/cache. Операции SET, GET и TTL используют контекст запроса с таймаутом 2 секунды. Ключ хранится 10 секунд. Отсутствующий ключ возвращает 404, недоступный Redis — 503.

## Запуск на macOS или Linux

Go 1.27.1, curl, Docker Desktop. Каждая практика — отдельный Go-модуль. Команды выполняются из этой папки.

```bash
docker compose -p go-pr7 up -d
go test ./...
go vet ./...
go run ./cmd/server
```

Файл `.env` читается оболочкой через `source`; автоматически сервер его не загружает. Порт API по умолчанию 8080. При одновременном запуске меняйте HTTP_ADDR, APP_ADDR (ПР9) или APP_PORT (ПР10).

## Проверки

Фактические результаты находятся в `evidence/`. Полные curl-команды и ответы — в `evidence/requests.txt` (для практик с HTTP-проверками). Тесты 15 и 16 записаны в `evidence/tests.txt` и `evidence/integration.txt`.

## Подготовка к защите

Redis хранит ключи и значения в памяти; PostgreSQL использует реляционную модель, SQL и ограничения целостности.

Кроме строк Redis поддерживает списки, множества, хэши, sorted sets и streams.

TTL задаёт срок жизни ключа. Он подходит для кэша, сессий и одноразовых кодов.

При cache hit запрос к основной БД не нужен. При miss приложение загружает данные из источника и заполняет кэш.

После истечения TTL GET возвращает redis.Nil. Это штатное отсутствие ключа.
